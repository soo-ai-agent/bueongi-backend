# 원천 CSV 원장

시설 데이터의 **초기 적재본**이다. 여기 있는 파일이 서버 기동 시 메모리 인덱스의 바탕이 되고,
이후 변경분은 API 증분(`clients/client-datagokr`)으로 따라잡는다.

**gzip 으로 저장한다.** 원본 합계 105MB 는 저장소에 영구히 남아 모든 clone 이 그 비용을 치른다.
압축하면 12MB 다. 적재 코드가 `.gz` 를 투명하게 읽으므로 푸는 작업은 필요 없다.

### CCTV·비상벨은 API 와 완전히 동기다

행 수가 API `totalCount` 와 **정확히 일치**한다(377,278 / 88,634). 따라잡기 호출이 필요 없다.

### ⚠️ 보안등은 잘린 파일이다

전국이 **1,839,475건**인데 CSV 는 딱 **50,000행** — 포털 다운로드 상한이다. 전체의 **2.7%** 이고
담긴 지자체가 **7곳**뿐이다(창녕군·김해시·여주시·평창군 등, 서울 없음).

| 제공기관코드 | 기관 | CSV | API |
|---|---|---:|---:|
| 5410000 | 경상남도 창녕군 | 10,041 | 10,041 (일치) |
| 5350000 | 경상남도 김해시 | 9,994 | 12,542 (CSV 가 잘림) |

**보안등만 CSV 로 못 덮는다.** 이 종류는 API `insttCode` 지역 단위 수집이 필요하다
(`제공기관코드` 가 곧 `insttCode` 다 — 위 표에서 창녕군 수치가 정확히 맞았다).
좌표 불량도 10%(5,091건)로 다른 종류보다 훨씬 높다.

## 행 수 ≠ 지점 수

CCTV 는 한 지점에 카메라 여러 대면 행이 나뉘어 있어 좌표 중복이 12.6만 건이다.
안전 점수는 지점 밀도를 세므로 적재할 때 좌표로 중복을 제거한다.

## 갱신하는 법

평소에는 갱신할 필요가 없다 — 변경분은 API 증분이 가져온다(CCTV·비상벨).
CSV 를 새로 받아야 할 때만 이 절차를 쓴다.

```bash
# 1) 포털에서 CSV 를 내려받아 backend/data/ 에 둔다
# 2) 압축해서 이 폴더로
gzip -9 -c "backend/data/<파일>.csv" > "backend/data/source/<파일>.csv.gz"
# 3) 위 표의 행 수·지점 수·갱신 범위를 다시 재서 갱신한다
# 4) 압축 안 한 원본은 커밋하지 않는다(.gitignore 의 *.csv 가 막는다)
```

## 왜 원본(.csv)은 커밋하지 않나

`backend/.gitignore` 의 `*.csv` 가 막는다. 압축본(`.gz`)만 예외로 추적한다 —
원본을 실수로 넣으면 9배 큰 파일이 히스토리에 영구히 박힌다.

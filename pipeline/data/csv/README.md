# data/csv: 오프라인 CSV 입력

공공데이터포털 등에서 내려받은 CSV를 원천 id 파일명(`{id}.csv`)으로 두면 파이프라인이 테스트 fixtures 다음의
최우선 입력으로 씁니다. CSV가 있으면 `data/raw/`와 라이브 API는 보지 않습니다.

## 파일 대응

| 파일명    | 원천                         | 다운로드                                          | 상태           |
|-----------|------------------------------|---------------------------------------------------|----------------|
| `B-1.csv` | 전국 CCTV 표준데이터         | data.go.kr 15013094                               | 없음           |
| `C-1.csv` | 서울 가로등 위치정보         | 서울 열린데이터광장 OA-22205                      | 있음(19,316행) |
| `C-2.csv` | 전국 보안등 표준데이터       | data.go.kr 15017320                               | 없음           |
| `C-3.csv` | 서울 보행등(보행신호등)      | 서울 열린데이터광장 OA-22354                      | 없음           |
| `C-4.csv` | 전국 스마트가로등 표준데이터 | data.go.kr `tn_pubr_public_smart_streetlight_api` | 있음(12,714행) |

- C-1과 C-3은 열린데이터광장에서 파일로만 열려 있어 라이브 API가 없습니다. 이 CSV가 운영 경로입니다.
- C-4는 라이브 스펙이 없어 CSV로만 들어갑니다.
- A-4(안심귀갓길)는 자치구별 좌표계가 달라 CSV 일괄 매핑 대상이 아닙니다. `A-4.csv`를 두면 경고만 남기고
  무시합니다.

## 열 매핑

CSV 열 이름은 `src/sources/fetchers.ts`의 `CSV_SPEC`과 일치해야 합니다.

| 파일      | 위도   | 경도   | 이름          | 주소             | 시군구         |
|-----------|--------|--------|---------------|------------------|----------------|
| `B-1.csv` | `위도` | `경도` | `관리기관명`  | `소재지지번주소` | `시군구코드`   |
| `C-1.csv` | `위도` | `경도` | `관리번호`    | `설치위치`       | 없음           |
| `C-2.csv` | `위도` | `경도` | `관리번호`    | `소재지지번주소` | `시군구코드`   |
| `C-3.csv` | `위도` | `경도` | `신호등 종류` | `주소`           | 없음           |
| `C-4.csv` | `위도` | `경도` | `도로명`      | `소재지지번주소` | `제공기관코드` |

- B-1은 `설치목적구분`, `카메라대수` 열도 읽습니다.
- C-2의 `CSV_SPEC` 열(`관리번호`, `시군구코드`)은 `sources.yaml`의 `keyColumns`(`보안등위치명`, `제공기관코드`)와
  다릅니다. 읽는 기준은 `CSV_SPEC`입니다.

## 주의

- 인코딩은 CP949(EUC-KR)와 UTF-8(BOM 포함)을 자동 판별합니다. 내려받은 파일을 그대로 둡니다.
- 헤더만 있거나 빈 파일은 무시하고 다음 입력으로 넘어갑니다.
- 저장소 `.gitignore`의 `*.csv` 규칙 때문에 새 CSV는 `git add -f`로 추가해야 추적됩니다.
